# i18n Workflow (12 Languages)

> ChinaConnect supports 12 languages: `en`, `ja`, `ko`, `zh-CN`, `zh-TW`, `th`, `vi`, `ru`, `fr`, `de`, `ar`, `fa`.
> The Chinese variants are for internal use; the other 10 languages target foreign visitors.

## Core rules

1. **Every key must exist in all 12 language blocks** in `src/i18n/translations.ts`. No English fallback.
2. **New keys fail CI** until added to every language. `pnpm check:i18n` enforces this.
3. **Future content (including blogs)** must be translated into all 12 languages. See "Adding a new key" below.

## File map

| File | Purpose |
|---|---|
| `src/i18n/translations.ts` | The single source of truth used at runtime. Built from per-language JSON files. |
| `<lang>-translations.json` (in repo root) | Per-language flat dot-key JSON, used as input to `merge-i18n.mjs`. |
| `scripts/check-i18n.mjs` | Build-time validator; exits 1 if any language is missing keys or any used key is missing in the en baseline. |
| `merge-i18n.mjs` | Reads all `<lang>-translations.json` and rebuilds `translations.ts` while preserving the existing nested structure. |
| `gen-missing.mjs` | Calls the LLM (MiniMax chat) to translate missing keys for any language. Resumable. |

## Adding a new key

```bash
# 1. Add the key to en in src/i18n/translations.ts (or any language block).
# 2. Translate into the other 11 languages. Either:
#      - Edit <lang>-translations.json manually (preferred for short additions), or
#      - Run: node gen-missing.mjs <lang>   (uses LLM, ~5-10 min per language)
# 3. Re-run the merge:
node merge-i18n.mjs
# 4. Verify:
pnpm check:i18n   # must print "OK: all languages have full coverage."
pnpm build        # must succeed
```

## Adding blog content

Blogs live under `src/content/blog/`. Astro i18n creates per-language routes automatically.
- Put each blog post in `src/content/blog/<lang-slug>/<post-slug>.md` (or whatever structure Astro expects).
- Translate frontmatter (title, description) for every language.
- The runtime i18n applies to UI strings; blog body content must be authored per language.

## Adding a new language

1. Add the new code to `Language`, `SUPPORTED_LANGUAGES`, `RTL_LANGUAGES` (if RTL), `CJK_LANGUAGES` (if CJK) in `src/i18n/translations.ts`.
2. Add an entry to the `translations` object literal (empty block is OK as a starter).
3. Add `<lang>.json` flat-key file in the repo root.
4. Run `node gen-missing.mjs <lang>` to translate all keys.
5. Run `node merge-i18n.mjs` and `pnpm check:i18n`.

## Emergency / bad translations

If a translation is wrong or missing:
- Edit the value directly in `src/i18n/translations.ts` (it's a plain object literal).
- OR edit `<lang>-translations.json` and re-run `node merge-i18n.mjs`.

## Why English fallback is forbidden

The user requirement: "中文只是给我和台湾人用的，主要面向的全部是外国人，包含所有的这些语言国家都需要逐个翻译".
Every page visitor sees text in their own language; English fallbacks look untranslated and hurt SEO + trust.
